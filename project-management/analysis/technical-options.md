# Options techniques — tmonier/sylius-punchout-cxml-plugin

> Phase 1 (Analyse) · 2026-10-14. Recommandations provisoires, à figer en Conception (tech spec + ADR).

| # | Sujet | Options | Recommandation provisoire |
|---|---|---|---|
| T1 | Sérialisation cXML | (a) `friendsofcxml/cxml-php` 2.2.5 · (b) `herbert/cxml` · (c) sérialiseur DOM maison (setup request en lecture ; setup response, order message, profile response en écriture) | **Spike en conception** : (a) si son parseur est sûr (pas de `LIBXML_NOENT`) et si le coût de jms/serializer est acceptable ; sinon (c). Dans tous les cas, **encapsuler derrière nos interfaces** (`CxmlParserInterface`, `CxmlWriterInterface`) pour rester remplaçable. (b) écarté (pas de versions). |
| T2 | OCI | (a) v1 · (b) v1.1 · (c) v2 | Implémentation maison (formulaires plats). Arbitrage de périmètre en Planification. |
| T3 | Configuration acheteur | Entité « PunchOut buyer » (ressource Sylius + grid admin) : identités `From` / `Sender` (domaine + identité), secret haché, protocole, canal, client ou entreprise rattaché, domaines autorisés pour l'URL de retour, `frame-ancestors`, mappings (UOM, UNSPSC, extrinsics), options taxes/port | Ressource Sylius dédiée ; secret **haché Argon2id** (seule la vérification est nécessaire) avec rotation (2 secrets actifs) |
| T4 | Authentification du setup | cXML : `Sender/Credential/SharedSecret` (+ contrôle `From`/`To`) ; OCI : `USERNAME`/`PASSWORD` ou token d'URL | Vérification sûre, réponse `401` générique, rate limiting (patron `symfony/rate-limiter` des autres plugins), anti-rejeu `payloadID` (table + TTL) et fenêtre de `timestamp` |
| T5 | Démarrage de session | (a) token à usage unique dans l'URL `StartPage` puis redirection · (b) cookie direct | **(a)** token 32 octets, TTL ≈ 5 min, consommé en GET puis redirection, `Referrer-Policy: no-referrer`, régénération de l'id de session |
| T6 | Identité dans la boutique | (a) connexion du ShopUser mappé (`Security::login` après contrôles) · (b) client sans compte (`setCustomer`) · (c) création auto à partir des `Extrinsic` | (a) par défaut (prix et groupes du client) ; (b) en option ; (c) à arbitrer en Planification |
| T7 | Panier | Contexte `#[AsCartContext(priority: 0)]` limité à la session PunchOut + `CartStorage::setForChannel` ; panier `createdByGuest = true` (`setCustomer`) | Retenu ; après transfert : session PunchOut close, panier détaché / supprimé selon option |
| T8 | Bouton et blocage du checkout | Voter `PUNCHOUT_SESSION` + `condition:` twig-hooks (bouton checkout, footer offcanvas) + bouton « Transférer » ; listener `kernel.request` (priorité 1-7) sur `sylius_shop_cart_checkout`, `sylius_shop_checkout_*`, `sylius_shop_order_*` ; guard `complete` (+ Doctrine winzou) | Retenu (pas de guard sur `address` : boucle de redirection) |
| T9 | Retour du panier | Page « sender » : formulaire auto-soumis `cXML-base64` (`target="_top"`), bouton « Annuler » (message vide) ; OCI : `NEW_ITEM-*` vers `HOOK_URL` | Retenu ; URL de retour revalidée contre la liste blanche au moment de l'envoi |
| T10 | Prix | Prix unitaire = prix après remises unitaires et part de promo commande, **HT** (retrait de la taxe incluse si TTC) ; `Total` = somme des articles hors taxes et port ; `Tax` / `Shipping` optionnels par acheteur | Retenu, avec tests HT / TTC et arrondis par unité |
| T11 | Classification / unités | Mapping UNSPSC (taxon → code, surcharge par produit) et UN/CEFACT (défaut `EA`/`C62`, surcharge) ; extension par interface taguée | Table de mapping du plugin + défauts configurables ; interface `ItemClassificationResolverInterface` |
| T12 | Iframe | Listener `kernel.response` (session PunchOut) : retrait `X-Frame-Options`, CSP `frame-ancestors` depuis la config acheteur ; cookie `SameSite=None; Secure` documenté côté application (+ commande de diagnostic) | Retenu ; CHIPS `Partitioned` en option ultérieure |
| T13 | Journal | Entité « message log » (direction, type, payloadID, statut, horodatage, empreinte / corps masqué) + grid admin, rétention configurable, commande de purge | Retenu (RGPD) |
| T14 | ProfileRequest | Réponse `ProfileResponse` listant `PunchOutSetupRequest` (+ `OrderRequest` si activé), `operationAllowed` | Retenu dès v1 (obligatoire pour cXML ≥ 1.1) |
| T15 | `edit` / `inspect` | Reconstruire le panier depuis les `ItemOut` (via `SupplierPartAuxiliaryID` = code variante + version) ; inspect = lecture seule ; sinon statut `450` | Arbitrage en Planification (exigé par certains acheteurs publics) |
| T16 | `OrderRequest` | Endpoint « order receiver » → commande Sylius (checkout piloté par les transitions, adresse `BillTo`/`ShipTo`, paiement « sur compte » / trade-credit) | Arbitrage en Planification (v1.1 ou v2 probable) |
| T17 | Intégrations optionnelles | company-accounts (mapping entreprise), quick-order (ajout groupé), tier-pricing (prix), chargées selon `kernel.bundles` | Pattern b2b-mcp ; v1 : company-accounts optionnel, adaptateur cœur pour l'ajout groupé |
