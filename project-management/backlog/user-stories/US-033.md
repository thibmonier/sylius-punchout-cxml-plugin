# US-033 — Secure OCI

> Epic : [EPIC-08](../epics/EPIC-08.md) · Persona : Outil d'achat · MoSCoW : **Could** · Points : **5** · Version : après v1.1
> Dépendances : US-012

## Story

En tant que SAP, je veux ouvrir le catalogue en Secure OCI, afin que les identifiants ne transitent pas par le navigateur.

## Valeur

Secure OCI (OCI 5.0 § 5.1) remplace les identifiants dans l'URL par un échange serveur-à-serveur (`SECURE_AUTH_URL`, `FUNCTION=INITIALIZE`, réponse `<SecureOCI>`).

## Critères d'acceptation

```gherkin
Fonctionnalité: Secure OCI

  Scénario: Initialisation serveur-à-serveur
    Étant donné l'acheteur "BigCorp SAP" en Secure OCI
    Quand SAP appelle l'URL d'authentification avec FUNCTION="INITIALIZE" et des identifiants valides
    Alors la réponse XML SecureOCI contient un identifiant de session à usage unique
    Et l'ouverture du catalogue avec cet identifiant connecte Claire sans identifiant dans l'URL
```

## Notes
