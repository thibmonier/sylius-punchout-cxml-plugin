# US-007 — Recevoir un PunchOutSetupRequest (create)

> Epic : [EPIC-02](../epics/EPIC-02.md) · Persona : Outil d'achat · MoSCoW : **Must** · Points : **8** · Version : v1
> Dépendances : US-001

## Story

En tant qu'outil d'achat, je veux envoyer un PunchOutSetupRequest et recevoir une URL de démarrage, afin d'ouvrir le catalogue du fournisseur pour Claire.

## Valeur

Point d'entrée du protocole.

## Critères d'acceptation

```gherkin
Fonctionnalité: Recevoir un PunchOutSetupRequest (create)

  Scénario: Setup valide
    Étant donné l'acheteur "BigCorp Ariba" configuré
    Quand l'outil d'achat poste un PunchOutSetupRequest operation="create" avec les bonnes identités et le bon secret
    Alors la réponse est un document cXML de statut "200"
    Et elle contient une StartPage/URL unique
    Et le document est valide contre la DTD cXML 1.2.071

  Scénario: Secret invalide
    Quand le secret est erroné
    Alors la réponse a le statut "401"
    Et aucune session n'est créée
    Et le message ne révèle pas quel élément est erroné

  Scénario: L'endpoint ne crée pas de cookie
    Quand l'outil d'achat poste un setup valide
    Alors la réponse ne contient aucun en-tête Set-Cookie
```

## Notes

Sprint 1 : authentification par secret simple (rotation dans US-002). BuyerCookie, BrowserFormPost, Extrinsic et ShipTo conservés dans la session PunchOut.
